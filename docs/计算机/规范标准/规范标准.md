### 1.3 API设计

#### 前端API设计

```
业务代码
   ↓ 调用
防腐层 (userService.getUserInfo)  ← 只关心这个稳定接口
   ↓ 调用
自定义 fetch (customFetch)         ← 统一封装请求、token、错误处理
   ↓ 请求
真实 API 接口 (https://api.xxx.com/user/123)
   ↓ 返回
ApiResponse<T> 格式数据

src/
├── api/
│   └── types/
│       └── api.ts         # 定义 ApiResponse<T>
├── services/              # 防腐层：所有 API 调用的门面
│   └── userService.ts     # 如：getUserInfo
├── utils/
│   └── fetchClient.ts     # 封装的 fetch，统一请求逻辑
└── pages/
    └── UserProfile.tsx    # 业务代码：只调用服务层，不关心请求细节
```

## 四、图片

| 类型           | 通道             | 位深（每个像素） | 颜色数       | 透明度支持                        | 文件大小 | 适用场景                     |
| :------------- | :--------------- | :--------------- | :----------- | :-------------------------------- | :------- | :--------------------------- |
| **PNG (通用)** | -                | -                | -            | 无损压缩                          | -        | 无损、支持透明，适合网络图像 |
| **PNG8**       | 1（索引）        | 8 bit            | 256 色       | ❌ 或 1-bit 透明（部分支持 Alpha） | 较小     | 简单图标、色彩少、体积优先   |
| **PNG24**      | 3（RGB）         | 8×3 = 24 bit     | 约 1677 万色 | ❌ 不支持透明                      | 中等     | 色彩丰富、无需透明           |
| **PNG32**      | 4（RGB + Alpha） | 8×4 = 32 bit     | 约 1677 万色 | ✅ 支持透明（半透明）              | 较大     | UI、图标、需要透明背景的图像 |
